# Milestone 3: rulings made during execution

Decisions taken on the owner's behalf while executing the M3 plan with subagents (2026-10-19), in the order they were made. Each line says what was found, what was decided, why, and what it costs if wrong. Rework anything you disagree with. The plan's "Deviations accepted in execution" block points here.

1. ## Rulings (pre-execution)
2. Ruling: as in M2, the plan carries interfaces, behaviours and tests in prose. Opus implementers write the component code, sonnet the data and rules task (Task 1). Every agent works in its own scratch directory and never edits repo files for experiments. Why: M2 showed that plan-authored UI code needed review fixes anyway. Cost if wrong: more reviewer load on the UI tasks.

42. Task 6: Ruling (I-1): re-importing the app's own CSV doubled every entry that was not itself imported (3 became 6 on the emulator). An `id` column is honoured only in the shapes this app writes: a 20-character auto-id, `imp_` and 24 hex digits, or `rec_<template>_<YYYY-MM>`. Any other id, a repeat of one in the same file and an empty cell fall back to the content id. Why the looser pre-ruling (any 1 to 64 characters without "/") loses data: another app's ids (1, 2, 3…) would make a second file overwrite the first file's entries, and Firestore refuses reserved ids such as `__x__`, `.` and `..`, which fail a whole batch of 400. Result: 3, 3 and 3 entries over two re-imports. Cost if wrong: a foreign file's own ids are ignored, and its rows get content ids.
