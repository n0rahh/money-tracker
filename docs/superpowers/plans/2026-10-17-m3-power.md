## Deviations accepted in execution

- **Recurring create (Tasks 1, 3):** a repeating entry is saved with `createRecurringWithFirstInstance(templateFrom(input))`: the template, with `lastAppliedMonth` = `startMonth`, and its first entry in one batch. Task 1's `createRecurring` and Task 3's `createRecurring` + `materialiseRecurring` pair are gone: the two writes let the materialiser write the first month again on 50 of 50 online saves.
- **Materialiser (Task 3):** it writes only from a server-confirmed snapshot (`subscribeRecurring(onData(templates, fromCache))` with `includeMetadataChanges`; `useRecurring()` also returns `fromCache`), at most 24 months per run (`monthsToMaterialise(t, now, max = 24)`, never before `startMonth`), skips malformed templates (`isMaterialisable`) and does not retry a failed batch in the same session.
- **Recurring page (Task 3):** "Delete template" deletes at once and offers Undo (`restoreRecurring`), no confirm. Stop shows only while a template runs past this month. An invalid template reads "Invalid template" instead of its schedule line and offers Delete only. Back returns through history. The Add sheet's switch sits after the category grid; the Settings row counts the templates that have not ended.
- **Rules and mapper (Task 1):** budgets split into `read, delete` and `create, update` (the literal read/write form denies reads); template ids are capped at 64 characters on create and update, never on read; `subscribeBudgets` delivers only limits above 0. `mapRecurring` keeps a malformed month field as it is instead of the planned "current month / null", so such a template is invalid and skipped (whole-branch review).
- **Budget rows (Task 2):** the bar line stays as on any other row, and a third line reads "<spent> of <budget>", then " · at limit" or " · <overage> over"; the share slot stays, empty. Only active expense categories count (`activeExpenseBudgets`). The maths live in `stats.ts`: `budgetProgress` returns `{ ratio, state: 'under' | 'at' | 'over', overage }`, plus `withBudgetRows` and `budgetSummary`. `CategoryEditSheet` also takes `currency` and `locale`.
- **Search (Task 4):** the bar opens above the day list, under the breakdown, and the page jumps it to the top; the icon stays in the header (placement pending the device pass). The predicate and the caption live in `src/lib/search.ts` (`matchesSearch`, `searchNeedle`, `foldForSearch`, `matchingCaption`, `KindFilter`): accents are folded and the caption's totals are signed. While a search is on, day headers total the matches only. `MonthPickerSheet` takes `locale` and marks this month.
- **Toasts (Task 5):** opening any `Sheet`, not only the Add form, takes away a toast that carries an action (`useDismissToastWhenOpened`, `dismissActionToast`). The live region is an always-mounted polite row. Every toast with a button (the 6 s Undo, the 10 s Share) waits while the pointer is over it or the focus is in it, then runs on with the time it had left. A stale chunk after a deploy reloads the page once (`src/lib/chunkReload.ts`, the `vite:preloadError` listener in `main.tsx`).
- **Exports (Task 6):** the reads use `getDocsFromServer`, not `getDocs`, so an offline export fails instead of saving part of the data; `getAllTransactions` reads the whole collection unordered (the builders sort). `getAllBudgets` and `getAllRecurring` feed the JSON: `buildJsonExport({ transactions, categories, budgets, recurring, currency }, now)`. `shareOrDownload` shares only on a touch device.
- **Import (Task 6, Global Constraints):** the content id hashes the category name in lower case, and each repeat of an identical row in the same file hashes its count in front, `1#`, `2#`, … (`importRowId(r, occurrence)`, `importRowIds(rows)`). An `id` column is kept only in this app's own id shapes, so the app's own CSV round-trips. The mapping also has `kindValues` (transfers skipped), one date order per file (`dateOrder`) and one decimal mark per column. Notes become one line and are cut to the rules' limits, and an empty category becomes "Other". `importTransactions` sends every batch at once (`allSettled`); `toCsv` also quotes `;`.
- **Tests (Tasks 3, 5, 6):** `tests/rules/` holds four files: the rules suite, plus three that run the app's own write and read functions against the real rules (Undo's restore, the recurring writes, import and export). `npm run test:scripts` is `node --test scripts/*.test.mjs` and runs in CI; `node --test scripts/` fails on Node 24. CI also runs `npm run build` (fix wave B).
- **Bundle (Global Constraints, Task 5):** the first paint is ≈ 302 kB gz of the 320 budget and all JS ≈ 323 kB gz of 350. Rolldown split the entry chunk in fix wave A; the split is accepted, with no config change.
- **Deploy (Task 7):** the rules go first: `npx firebase deploy --only firestore --project money-tracker-vlad`, about a minute's wait, then `npm run deploy`, rather than one `npm run deploy` (a phone that reloads before the rules apply runs against the M2 rules).

**Goal:** Monthly bills appear by themselves, budgets show how much room is left, old data can be imported and everything exported, a deleted entry can be undone, any month is reachable from a picker, the month list is searchable, and the app loads less code up front.

**Architecture:** Two new owner-only collections, `budgets/{categoryId}` and `recurring/{id}`, with rules validation and emulator tests. Recurring templates are materialised on the client (on launch and on each visibility tick) into ordinary transactions with deterministic ids `rec_<templateId>_<YYYY-MM>` written with `setDoc` in one batch per template together with `lastAppliedMonth`, which makes the operation idempotent across devices. Export reads the whole collections once (`getDocs`) and hands the user a file through the Web Share API when available, otherwise a download link; import parses CSV in the browser, lets the user map columns (auto-guessed from headers, so Money Manager exports work), creates missing categories and writes transactions in batches with deterministic ids derived from the row (re-import is idempotent). Undo re-creates a deleted transaction under its original id. Routes other than Home are lazy-loaded.

**Tech Stack:** unchanged — React 19, TypeScript strict, Vite 8, Tailwind v4, Firebase 13, react-router 7, Vitest 5 + Testing Library, lucide-react; no new dependencies (the CSV parser is ~60 lines, hashing uses `crypto.subtle`).

**Spec:** `docs/superpowers/specs/2026-10-14-money-tracker-design.md` — §6 (data model: later milestones add `budgets` and `recurring`, `recurringId`), §7 (Settings: export/import), §9 (Budgets, Recurring definitions), §10 "M3 — Power features" row, §11.

## Global Constraints

- All M1/M2 constraints hold: integer minor units, local ISO dates, 44 px targets, never-await writes with `.catch` → toast, Inter + `tnum`, pristine tests, conventional commits with the `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` trailer, no new dependencies, Spark plan only (no Functions/Storage).
- Rules remain the only security layer: every new collection is owner-only with schema validation, tested against the emulator; the `transactions` schema gains an optional `recurringId` (string, 1–64 chars) and `source` may be `'app' | 'shortcut' | 'import'`.
- Spec §9 definitions are binding: **Budgets** — a monthly limit per category; progress = category month total ÷ limit; over 100 % turns the bar `expense`-coloured. **Recurring** — templates applied client-side on app launch for any month between `startMonth` and now that is not yet materialised, creating ordinary transactions with `source: 'app'` and a `recurringId`.
- Deterministic ids: recurring instances `rec_${templateId}_${month}`; imported rows `imp_${sha256(kind|amount|categoryName|date|note).slice(0, 24)}`. Firestore ids may contain letters, digits, `_` and `-`.
- Export CSV columns, in order: `id,date,kind,amount,currency,category,note,source`; `amount` is a plain decimal in the stored currency (via `minorToDecimalString`); RFC 4180 quoting; UTF-8 with BOM so Excel opens it correctly; JSON export is `{ exportedAt, currency, categories: Category[], transactions: (Transaction with ISO strings for timestamps)[] }`.
- Production JS budget ≤ 350 kB gzipped total; after the lazy-route split the **initial** route chunk set (index + firebase + Home) must be ≤ 320 kB gzipped.

### Task 6: Export JSON/CSV and import CSV with column mapping

**Files:**
- Create: `src/lib/csv.ts`, `src/lib/csv.test.ts`, `src/lib/exporting.ts`, `src/lib/exporting.test.ts`, `src/components/ImportSheet.tsx`, `src/components/ImportSheet.test.tsx`, `scripts/mmbak-dump.mjs`
- Modify: `src/pages/SettingsPage.tsx` (+test), `src/lib/firestore.ts` (`getAllTransactions`, `getAllCategories`, `importTransactions`)

**Interfaces (pure, `src/lib/csv.ts`):**
- `parseCsv(text: string): string[][]` — RFC 4180: comma separated, `"` quoting with `""` escapes, quoted fields may contain commas and newlines, CRLF or LF, trailing newline ignored, a UTF-8 BOM stripped; auto-detects `;` as the separator when the header line has more `;` than `,`.
- `toCsv(rows: string[][]): string` — quotes fields containing `,`, `"`, `\n` or leading/trailing spaces; CRLF line ends; prefixed with a BOM.
- `type ColumnMapping = { date: number; amount: number; kind: number | null; category: number; note: number | null; signMeansExpense: boolean }`; `guessMapping(header: string[]): ColumnMapping | null` — case-insensitive header matching: date ∈ {date, data, datum}, amount ∈ {amount, sum, value, pln, eur, usd, …any 3-letter currency code, "amount (pln)"}, kind ∈ {kind, type, income/expense, inout}, category ∈ {category, categorie, kategoria, "category name"}, note ∈ {note, notes, description, memo, title}; `signMeansExpense` true when no kind column exists.
- `type ImportRow = { kind: Kind; amount: number; categoryName: string; date: IsoDate; note: string }`; `applyMapping(rows: string[][], mapping: ColumnMapping, digits: number): { ok: ImportRow[]; errors: { line: number; reason: string }[] }` — dates accepted as `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `YYYY/MM/DD`, `MM/DD/YYYY` (only when day > 12 disambiguates, else assume DD/MM); amounts accept `1 234,56`, `1,234.56`, `-12.50`, `(12.50)`; kind from the kind column (`income|in|earning|revenue` → income, else expense) or from the sign when `signMeansExpense` (negative → expense, positive → income; absolute amount stored); rows with a zero amount or an unparsable date/amount go to `errors` with a reason.
- `importRowId(r: ImportRow): Promise<string>` → `imp_` + first 24 hex chars of SHA-256 over `${kind}|${amount}|${categoryName.toLowerCase()}|${date}|${note}`.
