# Money Tracker — Milestone 4 (Siri & Apple Watch quick add) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** not started (written 2026-10-20 from main `9b35550`).

**Goal:** "Hey Siri, add expense" on the watch or the phone creates a transaction that appears in the app within seconds, with no server and no App Store: an Apple Shortcut signs in with an email/password credential linked to the owner's Google account and POSTs the entry to Firestore's REST API.

**Architecture:** Nothing new runs on a server. The app gains (1) a data layer that links, resets and removes a password credential on the signed-in Google user, (2) a small REST client that performs exactly the two HTTP calls the Shortcut performs (`accounts:signInWithPassword`, then `documents/transactions` create) so the owner can test the whole path in the app before building the Shortcut, (3) a lazy `/shortcut` page reached from Settings that holds the password step, the values to paste (project id, API key, email, category dictionaries), the test, and the recipe, and (4) an emulator test that runs the Shortcut's HTTP calls against the real rules through the Auth and Firestore emulators. The rules do not change: `source: 'shortcut'` is already allowed, and `email_verified` is what the owner's token carries after a password sign-in.

**Tech Stack:** unchanged — React 19, TypeScript strict, Vite 8, Tailwind v4, Firebase 13 (`linkWithCredential`, `updatePassword`, `unlink`, `reauthenticateWithPopup`, `sendEmailVerification`), react-router 7, Vitest 5 + Testing Library, lucide-react; `fetch` for the REST calls; no new dependencies. The Auth emulator joins `test:rules`.

**Spec:** `docs/superpowers/specs/2026-10-14-money-tracker-design.md` — §5 (auth; the email/password fallback "which Milestone 4 adds anyway for the Shortcut"), §6 (`source: "shortcut"`, auto-ids for Shortcut entries, `createdAt`/`updatedAt` optional), §7 (Settings), §10 "M4 — Siri & Apple Watch" row, §11, §14 (the recipe this plan finalises).

## Global Constraints

- All M1–M3 constraints hold: integer minor units, local ISO dates, 44 px targets, 16 px inputs, never-await Firestore writes with `.catch` → toast, Inter + `tnum`, pristine tests, conventional commits with the `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` trailer, no new dependencies, Spark plan only.
- Rules stay the only security layer and are not changed by this milestone. The Shortcut's document must satisfy `validTransaction` as it stands: `kind`, integer `amount > 0`, `categoryId`, `note` (≤ 200), `date` (`YYYY-MM-DD`), `at` (timestamp), `source: 'shortcut'`; no `recurringId`; no `createdAt`/`updatedAt` (the REST create cannot set server timestamps and the rules do not require them; the mapper already treats them as optional).
- The exact HTTP calls (binding for the client, the test and the docs):
  1. `POST https://identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key=<web API key>`, JSON `{"email":"<owner email>","password":"<password>","returnSecureToken":true}` → `idToken` (a JWT whose payload carries `email` and `email_verified`).
  2. `POST https://firestore.googleapis.com/v1/projects/<project id>/databases/(default)/documents/transactions`, headers `Authorization: Bearer <idToken>` and `Content-Type: application/json`, JSON `{"fields":{"kind":{"stringValue":"expense"},"amount":{"integerValue":"1250"},"categoryId":{"stringValue":"<id>"},"note":{"stringValue":""},"date":{"stringValue":"2026-10-20"},"at":{"timestampValue":"2026-10-20T17:05:00Z"},"source":{"stringValue":"shortcut"}}}` → `200` with the document (`name` ends in the new auto-id); `403 PERMISSION_DENIED` when the rules refuse; `401` for a bad token; `400` for a malformed body. `integerValue` is a JSON string; `timestampValue` is RFC 3339 and may carry an offset (`+02:00`) or `Z`.
- The password is generated in the app (24 characters from `A-Za-z0-9`, `crypto.getRandomValues`), shown once, copied by the owner into the Shortcut, and never stored by the app; whether one exists is read from `user.providerData` (`providerId === 'password'`).
- The owner enables the Email/Password provider once in Firebase Console → Authentication → Sign-in method (the app cannot; `auth/operation-not-allowed` on link means it is still off and the page says so). "Email link (passwordless)" stays off.
- Production JS budget unchanged: first paint ≤ 320 kB gz, total ≤ 350 kB gz; the page is a lazy route.

## Review Focus

1. A password sign-in whose token has `email_verified: false` must be refused by the rules and explained in the app: the emulator test pins the refusal (Task 1 Step 4, "unverified owner → 403"); the page decodes `email_verified` from the token and offers "Send verification email" (Task 2 Step 1 test "shows the verification button").
2. A dictated amount with a decimal comma or thousands separator ("12,50", "1 250") must become an integer minor-unit string: `firestoreFields` throws on a non-integer or non-positive amount (Task 1 Step 1 test), and the recipe fixes Ask for Input (Number) + Format Number with no grouping (Task 3 docs; Task 2 Step 1 test "recipe matches docs/shortcut.md").
3. A category archived or renamed after the dictionary was pasted still yields a valid write (the rules accept any `categoryId`), and the entry shows under that category in the app: the dictionary lists only active categories of one kind (Task 1 Step 1 test "excludes archived and other kinds"); the docs say to re-copy after changing categories (Task 3).
4. A failed or offline request from the test in the app must say what to do, not show JSON: `shortcutErrorText` maps `OPERATION_NOT_ALLOWED`, wrong-password codes, `PERMISSION_DENIED`, a network `TypeError` and `429` (Task 1 Step 1 tests).
5. Linking, resetting or removing the password after a long session must survive `auth/requires-recent-login`: the data layer reauthenticates with the Google popup once and retries (Task 1 Step 1 test "retries after reauthentication").

- `src/lib/shortcutRest.ts`:
  - `class ShortcutRestError extends Error { step: 'sign-in' | 'write'; status: number; code: string }` (`code` = identitytoolkit's `error.message` such as `INVALID_LOGIN_CREDENTIALS`, or Firestore's `error.status` such as `PERMISSION_DENIED`; `'NETWORK'` with status 0 when `fetch` throws).
  - `signInWithPassword(email: string, password: string, apiKey: string, hosts = DEFAULT_HOSTS): Promise<{ idToken: string; emailVerified: boolean }>` — `emailVerified` decoded from the JWT payload (base64url, second segment; `false` when absent).
  - `createTransactionViaRest(entry: ShortcutEntry, projectId: string, idToken: string, hosts = DEFAULT_HOSTS): Promise<{ id: string }>` — `id` is the last path segment of the response's `name`.
  - `shortcutErrorText(e: unknown): string` — `OPERATION_NOT_ALLOWED` → `Email/password sign-in is off. Turn it on in Firebase Console → Authentication → Sign-in method.`; `INVALID_LOGIN_CREDENTIALS` | `INVALID_PASSWORD` | `EMAIL_NOT_FOUND` → `Wrong password. Reset it in step 1 and paste the new one.`; `TOO_MANY_ATTEMPTS_TRY_LATER` → `Too many attempts. Try again in a few minutes.`; `PERMISSION_DENIED` → `Firestore refused the entry. The email must be the owner's and verified (see step 3).`; `NETWORK` → `You're offline.`; status `429` or `RESOURCE_EXHAUSTED` → the quota sentence of `readErrorText`; anything else → `Something went wrong (<code or status>).`
- `src/lib/shortcutAuth.ts`:
  - `hasPasswordProvider(user: User): boolean`
  - `linkShortcutPassword(user: User, password: string): Promise<void>` — `linkWithCredential(user, EmailAuthProvider.credential(user.email!, password))`.
  - `resetShortcutPassword(user: User, password: string): Promise<void>` — `updatePassword`.
  - `removeShortcutPassword(user: User): Promise<void>` — `unlink(user, 'password')`.
  - `sendShortcutVerificationEmail(user: User): Promise<void>` — `sendEmailVerification`.
  - all three mutations go through `withRecentLogin(user, fn)`: on `auth/requires-recent-login`, `reauthenticateWithPopup(user, googleProvider)` once, then `fn()` again.
  - `shortcutAuthErrorText(e: unknown): string` — `auth/operation-not-allowed` → the same console sentence as above; `auth/provider-already-linked` → `A Shortcut password already exists. Reset it instead.`; `auth/no-such-provider` → `There is no Shortcut password to remove.`; `auth/popup-closed-by-user` | `auth/cancelled-popup-request` → `Sign-in was cancelled.`; `auth/network-request-failed` → `You're offline.`; else the error's message or `Something went wrong`.
- `src/lib/firebase.ts`: `export const firebaseProjectId: string` and `export const firebaseApiKey: string` (the configured values; `''` when unconfigured).

The 14 recipe step titles (binding; the docs in Task 3 and the page in Task 2 use the same list):
1. Ask for Input — 2. Calculate — 3. Round Number — 4. Format Number + Replace Text — 5. Text (categories) — 6. Get Dictionary from Input — 7. Get Dictionary Value (All Keys) — 8. Choose from List — 9. Get Dictionary Value (the id) — 10. Get Contents of URL (sign in) — 11. Get Dictionary Value (idToken) — 12. Format Date (twice) — 13. Text (body) — 14. Get Contents of URL (write) + If + Show Notification.

Amended 2026-10-20 after the docs pass: step 4 strips every non-digit with Replace Text (`[^0-9]` → nothing) because Format Number has no grouping switch; step 13 is one Text action holding the whole `{"fields":{…}}` body; step 14 sends it as Request Body "File" with the `Authorization` and `Content-Type` headers and checks the result's `name` in an If before the notification, so a 4xx shows `error.message`. `shortcutAuthErrorText` also maps `auth/admin-restricted-operation` (the SDK links a password through `accounts:signUp`, which "Enable create (sign-up)" off blocks) → `Sign-up is turned off in Firebase Console (Authentication → Settings → User actions).
